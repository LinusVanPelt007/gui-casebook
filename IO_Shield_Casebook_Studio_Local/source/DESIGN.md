# Casebook Studio design language

## Structure
- The case is the center. Sessions, proof, skill claims, and portfolio stories live on the case page.
- Three pages: Cases (home), Skills, History. Everything else is a dialog or the casebook menu.
- One primary action per screen. "Log session" is always in the top bar.

## Forms
- Show only what a person has to decide. Anything that can be worked out goes under "Details".
- Infer, don't ask: IDs, hours from start/end, domains and context from the case, tools and work level from the last session, proof type from the file.
- Values typed once become suggestions next time.
- Files attach where the work is logged (drop, paste, or Attach). They become proof on the same case.
- Dropdown options come from the workbook's own validation lists, so customized sheets keep working.

## Writing
- No explanatory text blocks, banners, or taglines. Labels and placeholders carry the meaning.
- Errors say what to fix in one line.

## Visual
- Neutral surfaces, one accent (teal `--primary`). No decorative borders, accent bars, or eyebrows.
- Selection is shown by background only.
- System font. Monospace only for IDs. Tabular numbers for hours.
- Lists are rows in a single bordered container; hover shows a muted background.
- Badges are small pills. Green only for Verified or Approved.
